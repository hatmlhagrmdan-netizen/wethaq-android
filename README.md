# وَثاق

النسخة الحالية قيد التحقق الآلي من تطبيق وَثاق للتواصل.

- هوية المستخدم: الاسم الثلاثي + سنة الميلاد
- معرف وَثاق تلقائي
- تسجيل ودخول وحفظ الهوية
- البحث العام عن المستخدمين وإضافة جهات الاتصال
- محادثات ورسائل عبر REST وWebSocket
- حفظ الرسائل محليًا عند انقطاع الشبكة وإعادة إرسالها عند عودتها
- واجهة عربية RTL ومهيأة للهاتف
- خادم مستقل داخل `backend/`
- صلاحيات إدارة محمية من الخادم
- حظر مؤقت ونهائي وإلغاء الحظر
- نظام شكاوى للإدارة
- إصدار Android: `2.4.0` (`versionCode 8`)

## التحقق والتوقيع

مسار CI يبني نسخة تحقق منفصلة، ويجري فحص `apksigner verify --verbose --print-certs` وSHA-256 ويرفع Artifact للتحقق الهندسي. هذه النسخة ليست إصدار إنتاج.

أما **Wethaq Production Release** فهو مسار منفصل ومغلق بالفشل عند غياب أسرار التوقيع. لا يُنشئ إصدارًا إنتاجيًا بتوقيع اختبار أو توقيع Debug عند نقص الإعدادات.

للتوقيع الإنتاجي تُحفظ القيم التالية داخل GitHub Environment باسم `production`، وليس داخل المستودع:

- `WETHAQ_PRODUCTION_KEYSTORE_B64`: محتوى ملف JKS الإنتاجي بعد ترميزه Base64.
- `WETHAQ_KEYSTORE_PASSWORD`: كلمة مرور الـJKS.
- `WETHAQ_KEY_ALIAS`: Alias مفتاح الإنتاج.
- `WETHAQ_KEY_PASSWORD`: كلمة مرور المفتاح.

يجب تنفيذ مسار الإنتاج فقط بعد التأكد من أن الـJKS المستخدم هو مفتاح Wethaq الإنتاجي الصحيح، ثم يتم التحقق من APK بواسطة `apksigner` واستخراج شهادة التوقيع وSHA-256 قبل نشر الـArtifact.

يتضمن التحقق الآلي تدقيقًا بنيويًا، واختبارًا فعليًا لربط `better-sqlite3` الأصلي، واختبار Smoke لمسارات الهوية والبحث وجهة الاتصال والرسائل، ثم بناء APK وفحص سلامة التوقيع والملف.
