# تقرير تنفيذ تحسينات وَثاق — دفعة احترافية

## نطاق التنفيذ

تم تنفيذ التحسينات على فرع مستقل:

```text
improve/wethaq-professional-hardening
```

لم يتم دفع التغييرات إلى GitHub أو تعديل الفرع الرئيسي عن بُعد.

## التحسينات المنفذة

### الخادم والأمان

- إضافة محدد محاولات لمساري إنشاء الهوية وتسجيل الدخول:
  - إنشاء الهوية: 12 محاولة لكل IP/هوية خلال 15 دقيقة.
  - تسجيل الدخول: 8 محاولات لكل IP/هوية خلال 15 دقيقة.
- منع إعادة الصورة الشخصية بصيغة Base64 ضمن البحث العام؛ يعيد البحث حالة توفر الصورة فقط.
- تقليل صلاحية JWT الافتراضية:
  - جلسة المستخدم: 30 يومًا بدل سنة.
  - جلسة الإدارة: 12 ساعة بدل 30 يومًا.
- جعل مدد الجلسات قابلة للضبط عبر متغيرات البيئة.
- إضافة ترويسات حماية:
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `Referrer-Policy: no-referrer`
- توحيد CORS حول `ALLOWED_ORIGINS` مع دعم رجعي لـ`CORS_ORIGIN`، ومنع الاعتماد على wildcard في المثال الإنتاجي.
- توحيد `.env.example` وإضافة إعدادات TURN/STUN والجلسات.
- إصلاح Workflow التوقيع ليستخدم سر `WETHAQ_CERT_SHA256` بدل بصمة ثابتة داخل YAML.

### Android والجلسات

- إضافة `WethaqSession` يستخدم Android Keystore وAES-GCM لتخزين:
  - رمز جلسة المستخدم.
  - رمز جلسة الإدارة.
- إضافة هجرة تلقائية مرة واحدة من التخزين القديم إلى التخزين المشفر.
- تحديث MainActivity وAdminAccessActivity وخدمة الرسائل والإشعارات والمكالمات ولوحات الإدارة لاستخدام التخزين المشفر.
- إضافة إزالة للرموز المشفرة والقديمة عند تسجيل الخروج.
- إضافة `.gitignore` لمنع اعتماديات Node وملفات قواعد البيانات وملفات الأسرار ومخرجات البناء من التلوث في Git.
- توحيد نطاق Node.js إلى `>=22.13.0 <23` ليتوافق مع بيئة البناء الفعلية.
- إضافة `backend/package-lock.json` لإعادة إنتاج اعتماديات الخادم.

### الهوية البصرية وتجربة الاستخدام

- استخدام صورة التطبيق الحالية `profile_photo.jpg` بصريًا في:
  - شاشة الدخول.
  - الشاشة الرئيسية.
  - لوحة الإدارة العامة.
- إبقاء هوية وَثاق وشعارها ضمن نفس التسلسل البصري: صورة حية، هوية العلامة، ثم الإجراءات.
- إضافة `contentDescription` للشعار وصور المؤسس وصور المستخدمين وشاغلي المناصب لدعم TalkBack.
- منع شاشة التطبيق من الظهور بشكل أبيض أثناء الإقلاع عبر تحسين إعداد الثيم.
- الحفاظ على الألوان الأساسية الحالية: الأزرق الليلي، الذهبي، والأبيض، دون إدخال أصول خارجية أو صور وهمية.

## ملاحظة تشغيل الاختبارات

تشغيل `security-smoke-test.mjs` و`smoke-test.mjs` على نفس عملية الخادم قد يشارك ذاكرة rate limiter بين الاختبارات. لذلك تم تشغيل الاختبارات النهائية على عمليات منفصلة وقواعد بيانات مؤقتة نظيفة، وهو الأسلوب الصحيح لعزل الاختبارات.

## القيود المتبقية

- لم يتم بناء APK محليًا لغياب Gradle وAndroid SDK من بيئة Sandbox الحالية.
- لم يتم إجراء اختبار بصري على محاكي/جهاز فعلي في هذه البيئة.
- لم يتم اختبار مكالمة صوت وفيديو حقيقية بين جهازين وشبكتين مختلفتين.
- لا تزال بنية Android تعتمد على واجهات برمجية داخل ملفات Java كبيرة، ويُوصى لاحقًا بالانتقال التدريجي إلى طبقات ViewModel/Repository وRecyclerView.
- لا يزال تخزين الوسائط في SQLite/Base64 قائمًا؛ النقل إلى Object Storage هو التحسين التالي للتوسع العالمي.

## التوصية قبل الدمج

1. تشغيل GitHub Actions على هذا الفرع.
2. مراجعة سر بصمة الشهادة في إعدادات GitHub Actions والتأكد من أنه يطابق شهادة الإنتاج الحالية.
3. تثبيت APK على جهازين حقيقيين واختبار الدخول، الصور، الرسائل، الإشعارات، ولوحات المناصب.
4. إجراء مراجعة أمنية خارجية قبل فتح التسجيل العام.
5. بعد نجاح ذلك، دمج الفرع عبر Pull Request وليس نسخ الملفات يدويًا.
