# Wethaq — Identity & Administration UX

## الهدف
إضافة طبقة هوية وإدارة واضحة فوق النظام الحالي دون استبدال المصادقة أو الرسائل أو المكالمات أو الإشعارات الموجودة.

## الهوية العادية
- الاسم الثلاثي
- سنة الميلاد
- الرمز الشخصي
- لكل حساب `wethaq_id` فريد يمثل هوية وَثاق ولا يعتمد على الاسم وحده.
- البحث والعرض والجهات المحفوظة تستخدم `wethaq_id` لتجنب تشابه الأسماء.
- عند استخدام جهاز جديد تبقى هوية المستخدم مرتبطة بالمعرّف الفريد، مع إبقاء التحقق بالمعلومات السرية الحالية وعدم إنشاء مسار دخول أضعف.

## الدخول الإداري
مسار مستقل عن جلسة المستخدم العادية:
- الاسم الثلاثي
- سنة الميلاد
- الرمز الإداري السري للمنصب

الرمز الإداري ليس بديلًا عامًا للرمز الشخصي؛ بل رمز مستقل لكل تعيين نشط، ويجب تخزينه بصورة غير قابلة للاستخراج، وإبطاله عند إزالة المنصب أو انتهاء صلاحيته.

## الدليل العام
يعرض الرتبة، العدد، الرسم، الصلاحيات المختصرة، والأسماء الفعلية للمعينين. المقعد غير المشغول يظهر `شاغر`. لا يعرض أي رمز سري أو جلسة أو token.

عند التعيين يظهر اسم الشخص تلقائيًا في الرتبة المناسبة، مع `تم التعيين بواسطة` واسم ورتبة المعين. عند الإزالة يختفي التعيين من الدليل، بينما يبقى الحدث في سجل التدقيق.

## بطاقة التعيين الخاصة
بعد نجاح التعيين، يرسل النظام رسالة خاصة للمُعيّن تتضمن التهنئة، الرتبة، رمز المنصب السري، جهة التعيين، وتعليمات التواصل مع مدير ومؤسس وَثاق لبدء المهمة. يجب التنبيه أن الرمز سري ومخصص لهذا الحساب وهذا المنصب.

## قاعدة أمان مهمة
الواجهة ليست مصدر الحقيقة للصلاحيات. الخادم هو الذي يتحقق من الرتبة، العدد، نطاق الحظر/التحذير، حالة الاشتراك، وصلاحية الرمز الإداري. أي زر إداري في Android أو الويب يجب أن يعكس صلاحيات الخادم ولا يمنحها محليًا.
